# 3DGRT 1/64 Sparse-Ray 학습 실험 보고서

> 작성일: 2026-08-05
> 현재 단계: **학습(training) 가속 — Gaussian 모델을 sparse ray만으로 처음부터 학습**

> 핵심 결과: Bonsai 장면을 1/64 stratified primary ray만으로 30,000 step 처음부터 학습해 전체 37개 test view 기준 **31.293 dB**를 얻었다. Full-ray 학습(31.662 dB) 대비 **-0.369 dB에 학습 시간 14.3배**(7시간 22분 → 약 31분)다.



## 1. 배경

### 1.1 이전 실험과의 차이

이전에는 모두 **학습된 Gaussian 모델을 고정한 채** Denoiser만 학습했고, 따라서 학습 가속은 주장할 수 없었고 Denoiser를 포함한 Denoising구조에서 학습을 진행한 적은 없다. 본 실험은 처음으로 그 제약을 푸는데 Denoiser를 어떻게 학습구조에 붙일지, 또 sparse-ray만 가지고 학습할 경우의 품질은 어떤지에 대한 선행연구다. 

**즉 Gaussian 자체를 sparse ray로 학습시키고, 그 결과가 full-ray 학습과 얼마나 다른지를 묻는다.**

### 1.2 연구 질문

> **(Q1)** primary ray를 1/64로 줄인 채 장면을 처음부터 학습하면 품질을 얼마나 잃는가?

> **(Q2)** 그 손실은 어디에 있는가 — 무작위로 퍼져 있는가, 아니면 구조적으로 특정 대역에 몰려 있는가?

> **(Q3)** sparse로 학습한 장면은 추론 비용도 달라지는가?

### 1.3 실험 조건

Bonsai 단일 장면, **downsample factor 1**(2078×3118, 6,479,204 px)이다. 

- 학습 255장 / test 37장, `test_split_interval=8`, 두 집합의 교집합은 0장이다.
- 평가는 항상 **37개 test view 전체**에 대해, 항상 **full-ray**로 수행한다.
- GPU는 NVIDIA GeForce RTX 4070 SUPER 12 GB이며, 두 학습 모두 GPU를 단독 점유한 상태에서 측정했다.

## 2. 학습 설정

핵심 설계 원칙은 하나다. **sparse화를 배치(batch) 한 지점에만 넣고, 나머지 학습 기구는 건드리지 않는다.**

3DGRT의 학습 루프는 `model(gpu_batch)`로 렌더링한 뒤 `get_losses(gpu_batch, outputs)`를 호출한다. 따라서 배치를 그 1/64 부분집합으로 치환하면 — compact ray 텐서와, 정확히 그 픽셀 위치에서 모은 ground truth로 — densification, learning rate 스케줄, progressive spherical harmonics를 포함한 모든 기구가 손상되지 않은 채로 남는다. 손실 정의도 별도로 구현할 필요가 없다.

### 2.1 포워드 (forward)

매 step 원해상도 격자를 8×8 블록으로 나누고, 각 블록에서 픽셀 하나를 균등하게 뽑는다(stratified sampling with jitter). 뽑힌 좌표로 ray origin·direction·ground truth를 gather해 260×390 텐서로 재배열한다.

```python
samples = sample_stratified_pixels(height, width, block, block,
                                   generator=self.generator, device="cuda")
return Batch(
    rays_ori=gpu_batch.rays_ori[:, samples.y, samples.x]
             .reshape(1, grid_h, grid_w, 3).contiguous(),
    rays_dir=gpu_batch.rays_dir[:, samples.y, samples.x]
             .reshape(1, grid_h, grid_w, 3).contiguous(),
    T_to_world=gpu_batch.T_to_world,
    rgb_gt=gpu_batch.rgb_gt[:, samples.y, samples.x]
           .reshape(1, grid_h, grid_w, 3).contiguous(),
    intrinsics=gpu_batch.intrinsics,
)
```

세 가지가 중요하다.

**첫째, 저해상도 렌더링이 아니다.** ray는 원해상도 픽셀 위치를 그대로 쏘고, 결과만 260×390 텐서에 담긴다. 카메라를 축소해 렌더링하는 것과는 다르며, 260804에서 쓴 "원해상도 active mask" 방식과도 다르다. mask 방식은 마스킹된 ray도 여전히 발사되므로 비용이 줄지 않는다. compact 텐서는 실제로 101,400개 ray만 발사한다.

**둘째, jitter를 매 step 다시 뽑는다.** 블록 중심에 고정하면 학습 내내 같은 101,400개 픽셀만 감독하게 되어 나머지 98.4%는 한 번도 관측되지 않는다. 매 step 재추첨하면 추정량이 불편(unbiased)이 되고, 30,000 step에 걸쳐 모든 픽셀이 기대값 상 같은 횟수만큼 관측된다. (블록 중심 고정은 추론 단계에서만 쓴다 — 그때는 분산이 아니라 결정성이 필요하기 때문이다.)

**셋째, ray 수와 비용이 선형으로 연동되지 않는다.** ray를 64배 줄였지만 학습 시간은 14.3배만 빨라졌다. 나머지 4.5배는 260805 보고서에서 분해한 두 요인이다 — 흩어진 ray는 warp 안에서 서로 다른 BVH 노드를 타므로 ray coherence가 3.3배 나빠지고, 발사되는 ray가 적어 GPU occupancy가 1.8배 떨어진다. 이는 구현 결함이 아니라 sparse ray tracing의 구조적 성질이다.

**검증.** `[sparse] step 0` 로그 한 줄은 최초 1회만 출력되는 래치라서 증거가 되지 않는다. 별도로 렌더러와 손실 함수의 입력 텐서를 300 step 전부 계측했다.

```
rendered   (1, 260, 390, 3) x 300      = 101,400 rays / step
loss pred  (1, 260, 390, 3) x 300
loss gt    (1, 260, 390, 3) x 300
```

dense step이 한 번도 새지 않았고, 손실이 본 예측과 ground truth의 형상도 매 step 동일했다.

### 2.2 손실 (loss)

설정은 dense 학습과 동일하다.

| 항 | 가중치 |
|---|---:|
| L1 | 0.8 |
| SSIM | 0.2 |
| L2 / opacity / scale | 사용 안 함 |

배치 치환의 결과로 **지도교수님이 지정한 손실이 그대로 나온다.**

- **L1은 샘플된 픽셀 위에서만 계산된다.** 배치에 그 픽셀들밖에 없기 때문이다. 별도 마스킹이 필요 없다. (`get_losses`는 `gpu_batch.mask`를 읽지만 Bonsai에는 mask가 없어 `None`이다.)
- **SSIM은 1/64 downsample 격자 위에서 계산된다.** 260×390 텐서가 곧 jitter mask를 적용한 downsample이다.

SSIM을 격자 위에서 계산하는 것은 선택이 아니라 필연이다. SSIM은 이웃 윈도우를 필요로 하는데, 흩어진 샘플에는 이웃이라는 개념이 없다. 격자로 모으면 이웃이 생기지만, **그 대가로 11×11 윈도우가 원해상도 88×88 픽셀에 대응하게 된다.** 즉 구조 항이 감독하는 공간 스케일이 dense 학습보다 8배 거칠어진다. 3.3절에서 측정하는 고역 열화의 직접적인 원인이 여기에 있다.

### 2.3 백워드 (backward)

**그래디언트는 101,400개 ray를 통해서만 흐른다.** 3DGRT의 backward는 forward와 같은 ray를 다시 순회하며 hit한 Gaussian에 기여를 누적하므로, backward 비용도 forward와 같은 방식으로 ray 수에 연동된다. sparse 학습이 빠른 이유의 절반은 여기에 있다.

**Denoiser는 그래디언트 경로에 없다.** 이는 의도적이다. 수렴된 다른 장면에서 학습한 Denoiser를 넣으면, 학습 초기의 분포 밖 입력에 대해 Denoiser가 잘못된 그래디언트를 흘려 geometry를 왜곡할 수 있다. 본 실험은 그 교란 없이 "sparse 감독만으로 장면이 서는가"를 먼저 묻는다. Denoiser를 그래디언트 경로에 넣는 것은 다음 단계다(5장).

**어떤 Gaussian이 그래디언트를 받는가.** 샘플된 ray가 hit한 Gaussian 전부다. 여기서 흔한 오해를 짚어둘 필요가 있다 — sparse 학습이 빠른 이유는 "일부 Gaussian만 갱신해서"가 아니다. Gaussian 하나가 화면에서 A개 픽셀을 덮는다면 dense 학습에서는 step당 A개의 픽셀 기여를, sparse 학습에서는 기대값 A/64개를 받는다. 즉 **그래디언트는 편향되지 않고 분산만 약 8배(√64) 커진다.** Adam이 30,000 step에 걸쳐 그 분산을 평균내므로 수렴점 자체는 크게 이동하지 않는다. 이것이 -0.369 dB라는 작은 격차의 근본 이유다.

바꿔 말하면, sparse 학습이 잃는 것은 **그래디언트의 정확도가 아니라 관측의 공간 해상도**다. 그리고 그 손실은 무작위로 퍼지지 않고 특정 주파수 대역에 몰린다(3.3절).

### 2.4 Densification 전략

설정값은 dense 학습과 동일하다.

| 항목 | 값 |
|---|---|
| 방식 | GSStrategy (clone + split) |
| densify 주기 / 구간 | 300 step / 500 – 15,000 |
| prune 주기 / 구간 | 100 step / 500 – 15,000, density < 0.005 |
| density reset | 3,000 step마다, 최대 0.01 |
| 최대 Gaussian 수 | 2,000,000 |
| relative size threshold | 0.01 |
| clone / split grad threshold | dense **0.0002** → sparse **0.0003254** |

**단 한 곳만 바꿨다 — grad threshold다.** 그 이유는 다음과 같다.

`GSStrategy.update_gradient_buffer`는 Gaussian마다 **step별 위치 그래디언트의 노름**을 취한 뒤 그 노름들을 평균한다. 노름은 볼록 함수이므로 옌센 부등식에 의해

```
E[ ||g|| ]  >=  || E[g] ||
```

이고, 등호는 g에 분산이 없을 때만 성립한다. 2.3절에서 본 것처럼 sparse 감독은 g를 불편하게 유지하면서 분산만 키우므로, **그래디언트 자체는 편향되지 않았는데 densification이 읽는 통계량은 부풀려진다.** 임계값을 그대로 두면 과도하게 clone/split이 일어난다.

누적 기간을 늘려도 해결되지 않는다. 부풀림은 이미 각 step의 노름 안에 들어가 있기 때문이다. 벡터를 누적한 뒤 마지막에 노름을 취하면 부풀림은 사라지지만, 서로 다른 view가 밀어내는 방향이 상쇄되어 3DGS densification이 의존하는 신호 자체가 없어진다. 따라서 보정은 임계값 재조정일 수밖에 없다.

260804(§39)에서는 이 배율을 1.8로 **추측**했고 과보정되어 Gaussian 수가 dense 대비 15% 부족했다. 본 실험에서는 수렴된 장면에서 dense/sparse 통계량을 직접 누적해 **중앙값 비 1.627을 실측**하고, 0.0002 × 1.627 = 0.0003254를 사용했다.

결과는 **1,221,706개**로 dense의 1,265,883개 대비 **-3.5%**다. 추측 보정의 -15%에서 크게 개선됐다.

**남은 미해명 항목.** 같은 측정에서 상위 1% 순위 중첩률은 52%에 그쳤다. densification은 통계량이 큰 것부터 고르므로 순위가 절반만 보존되면 서로 다른 Gaussian이 분열해야 하는데, 실제 품질 손실은 작았다. 순위 교란이 왜 무해했는지는 아직 설명하지 못했다.

## 3. 정량 결과

### 3.1 네 가지 구성

추론의 denoiser 구성은 260805 보고서에서 확정한 운용점(base를 1/2 해상도·hit threshold 0.06으로 렌더 + 1/64 블록 중심 ray + 잔차 bilinear 업샘플, 네트워크 없음)을 그대로 쓴다. D는 그 denoiser마저 뺀 것으로, 1/64 ray를 그대로 bilinear 업샘플한 것이다.

| # | 학습 | 추론 | PSNR | SSIM | 렌더 시간 | FPS |
|---|---|---|---:|---:|---:|---:|
| A | full-ray | full-ray | **31.662** | 0.9314 | 291.1 ms | 3.44 |
| B | **1/64** | full-ray | 31.293 | 0.9239 | 244.1 ms | 4.10 |
| C | **1/64** | 1/64 + denoiser | **31.201** | 0.9229 | **44.8 ms** | **22.31** |
| D | **1/64** | **1/64 ray만** | 27.859 | 0.8558 | 15.49 ms | 64.56 |

읽는 방법은 네 가지다.

**학습만 sparse화 (A → B): -0.369 dB, 학습 14.3배.**
추론은 그대로 두고 학습 비용만 줄인 경우다.


**양쪽 다 sparse화 (A → C): -0.461 dB, 학습 14.3배 · 추론 6.50배.**
두 축의 손실이 -0.369와 -0.143로 단순 합산하면 -0.512인데 실제는 -0.461이므로, **두 손실은 완전히 독립이 아니고 약간 겹친다.**

**denoiser를 빼면 (C → D): -3.342 dB.**
1/64 ray만으로는 27.859 dB에 그친다. 속도는 15.49 ms로 A 대비 18.8배까지 가지만, 품질 격차가 -3.803 dB로 벌어져 쓸 수 없는 지점이다. 이 3.342 dB가 **denoiser가 실제로 하는 일의 크기**이며, 동시에 1/64 ray 자체가 담고 있는 정보의 상한이기도 하다. 8픽셀 간격의 샘플은 0.0625 cycles/px 위를 표현할 수 없으므로(3.3절), 그 위의 성분은 어떤 업샘플로도 복원되지 않는다. denoiser는 바로 그 성분을 별도 경로로 공급하는 장치다.

이 마지막 대비는 한 가지를 더 시사한다. 학습에서는 denoiser 없이도 -0.369 dB에 그쳤는데 추론에서는 같은 1/64가 -3.434 dB를 낸다. **학습과 추론에서 sparse ray의 의미가 다르기 때문이다.** 학습에서는 매 step 다른 픽셀을 뽑아 30,000 step에 걸쳐 정보가 누적되지만(2.1절, 픽셀당 468.8회), 추론에서는 단 한 번의 관측으로 끝난다.

겹침은 다음 대비에서 더 분명하다.

| 각 모델을 자기 자신의 full-ray 기준으로 볼 때 | 1/64 + denoiser 추론 손실 |
|---|---:|
| full-ray 학습 모델 | -0.143 dB |
| **1/64 학습 모델 (B → C)** | **-0.092 dB** |

**sparse로 학습한 장면은 sparse 추론에 더 강하다.** 이유는 3.3절에서 드러난다 — sparse 학습 모델은 애초에 나이퀴스트 위 성분을 덜 갖고 있어서, 1/64 샘플로 복원할 때 잃을 것이 더 적다.

### 3.2 학습 비용

| | full-ray 학습 | 1/64 학습 |
|---|---:|---:|
| step당 ray | 6,479,204 | 101,400 (1/64) |
| step 수 | 30,000 | 30,000 |
| 총 시간 | 7시간 22분 | **약 31분** |
| Gaussian 수 | 1,265,883 | 1,221,706 (-3.5%) |

**14.3배**다. ray 축소율 64배와의 차이는 2.1절의 ray coherence·occupancy 요인이다.

한 가지 주의: 초기 학습의 step 시간은 정상 상태와 크게 다르다. COLMAP 초기화 직후에는 Gaussian이 커서 ray당 hit 수가 70.5인 반면 수렴 후에는 30.4다. 학습 중반의 순간 측정치를 정상 상태로 오인하면 오버헤드 비중을 크게 과대평가하게 된다.

### 3.3 오차가 어디에 있는가 — PSNR이 가리는 것

PSNR은 -0.369 dB인데 SSIM은 -0.0075로 불균형하게 떨어졌다. 오차가 고르게 퍼진 것이 아니라 뭉쳐 있다는 신호다.

1/64 샘플링은 8픽셀 간격이므로 원리적으로 **1/(2·8) = 0.0625 cycles/px** 위의 성분을 표현할 수 없다. 그리고 2.2절에서 본 것처럼 SSIM 항은 8배 downsample된 격자에서 돈다. 즉 **학습 목적함수는 그 한계 위의 대역을 구조적으로 볼 수 없다.** 각 렌더를 8×8 박스 평균(= SSIM 항이 실제로 돈 격자)과 그 나머지로 분해하면:

| 대역 | full-ray 학습 | 1/64 학습 | 차이 |
|---|---:|---:|---:|
| 저역 — **손실이 감독한 대역** | 33.667 | 33.472 | **-0.195** |
| 저역 SSIM | 0.9687 | 0.9707 | **+0.0020** |
| 고역 — **나이퀴스트 위, 감독 불가** | 36.555 | 35.873 | **-0.682** |

**격차의 약 2/3가 목적함수가 볼 수 없는 대역에 있다.** 감독한 대역에서는 sparse가 dense와 사실상 동률이고, SSIM은 오히려 근소하게 낫다.

전해상도 PSNR은 저주파 에너지가 지배하므로 고역의 열화를 과소 반영한다. 따라서 **-0.369 dB를 "sparse 학습은 사실상 공짜"로 인용하면 안 된다.** 정확한 진술은 *감독한 대역에서는 거의 공짜이고, 감독하지 못한 대역에서 대가를 치른다*이다.

**형상 통계도 같은 방향을 가리킨다.**

| | Gaussian 수 | 크기 중앙값 | 불투명도 중앙값 | 이방성 > 10 |
|---|---:|---:|---:|---:|
| full-ray 학습 | 1,265,883 | 0.01141 | 0.1676 | 35.2% |
| 1/64 학습 | 1,221,706 | **0.00895** | **0.0979** | 37.5% |

sparse 학습 모델의 Gaussian은 더 작고 더 흐리다. 샘플 사이로 빠질 만큼 미세한 구조는 그것이 중간 픽셀에 무슨 짓을 하든 벌점을 받지 않으므로, 아무것도 그것을 막지 않는다. 4장의 크롭에서 보이는 바늘 모양 streak가 이 대역의 실체다.

**부수적 결과 — 추론이 더 싸다.** sparse 학습 모델은 Gaussian이 3.5% 적은데 full-ray 렌더 시간은 291.1 ms → 244.1 ms로 **0.84배**다. 추론 비용을 정하는 것은 Gaussian 개수가 아니라 ray당 hit 수인데, 그것이 29.34 → 28.59로 낮아졌기 때문이다. 즉 sparse 학습은 학습만 싸게 만드는 것이 아니라 **더 싼 장면을 만들어낸다.**

## 4. 정성 결과

모든 패널은 아래 네 구성이며, 3.1절의 기호를 그대로 쓴다. 각 패널 제목의 dB는 **그 뷰 하나의 PSNR**이다.

| 기호 | 학습 | 추론 |
|---|---|---|
| **A** | full-ray | full-ray |
| **B** | 1/64 | full-ray |
| **C** | 1/64 | 1/64 + denoiser |
| **D** | 1/64 | 1/64 ray만 |

여섯 번째 패널 `|B - A| x5`는 **B와 A의 절대 차이를 5배 증폭**한 것이다. sparse 학습이 full-ray 학습과 어디서 갈라지는지를 직접 보여주며, 검을수록 두 학습이 같은 결과에 도달했다는 뜻이다.

### 4.1 최악 구간 크롭 — 원해상도

각 뷰에서 A 대비 B의 제곱오차가 가장 큰 360×360 창을 적분영상으로 찾아 **원해상도 그대로** 잘라냈다. 앞의 다섯은 격차가 가장 큰 뷰이고, 뒤의 셋은 중간값 부근과 sparse가 오히려 이긴 경우를 함께 보기 위해 추가했다.

세 가지가 눈에 띈다.

**첫째, B의 열화는 흐려짐이 아니라 잘못된 고주파의 삽입이다.** 물체 경계에서 뻗어 나오는 바늘 모양 streak가 sparse 학습 쪽에만 나타난다. 3.3절에서 측정한 고역 -0.682 dB의 시각적 실체다. 일부 영역에서는 B가 A보다 오히려 **더 선명하다** — A가 뭉갠 잎맥이 B에서는 살아 있다.

**둘째, D는 완전히 다른 종류의 실패다.** 8픽셀 간격 샘플을 그대로 업샘플했으므로 블록 계단이 그대로 보이고 미세 구조가 통째로 사라진다. C와 D의 간격이 3.1절의 -3.342 dB이며, denoiser가 메우는 것이 바로 이 구간이다.

**셋째, C는 B에 거의 붙어 있다.** 추론을 1/64로 줄인 대가(-0.092 dB)가 학습을 1/64로 줄인 대가(-0.369 dB)보다 작다는 정량 결과와 일치한다.

## 5. 한계와 다음 단계

### 5.1 본 실험이 주장하지 않는 것

- **단일 장면이다.** Bonsai 하나이며, 다른 장면에서 같은 배율이 나오는지는 확인하지 않았다.
- **Denoiser가 학습에 관여하지 않았다.** 본 결과는 순수하게 sparse 감독만으로 얻은 것이다.
- **densification 순위 교란(52% 중첩)이 왜 무해했는지 설명하지 못했다.**

### 5.2 다음 단계

3.3절의 대역 분해는 다음 단계를 직접 지시한다. **열화는 목적함수가 보지 못하는 대역에 있으므로, 그 대역을 목적함수에 보이게 만드는 것이 유일한 해법이다.** 1/64 샘플을 원해상도로 되돌리는 것은 재구성 연산자이므로, Denoiser를 그래디언트 경로에 넣어야 비로소 손실이 지금 무너지는 대역을 본다.

즉 순서는 이렇다.

1. **(완료)** sparse 감독만으로 장면이 서는가 → 선다. -0.369 dB, 14.3배.
2. **(다음)** 재구성 연산자를 그래디언트 경로에 넣어 고역을 감독한다.
3. 희소도 곡선을 그려 1/64의 위치를 확정한다.
