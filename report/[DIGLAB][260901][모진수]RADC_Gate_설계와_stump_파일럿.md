## 요약

이번 리포트의 핵심 발견은 세 가지다.

### 발견 1 — 관측이 부족한 Gaussian 을 densification 후보에서 제외하면 stump 의 Gaussian 수가 dense의 1.531배에서 0.885배로 내려가고 PSNR 은 실행 변동 범위 안에서 유지된다

지도받은 RADC-Gate 를 구현해 stump downsampling 4 에서 시험했다. 게이트는 densify 주기
동안 누적한 관측 step 당 평균 ray 적중 수 `h` 가 임계 `θ` 이하인 Gaussian 의 densification
통계량을 0 으로 만들어 clone 과 split 후보에서 제외한다. 제거가 아니라 성장 배제이므로
그 Gaussian 은 계속 학습되고 계속 렌더링되며 다음 주기에 다시 판정받는다.

Ray 를 1/16 로 줄인 조건에서 `θ = 1.0` 으로 3회 반복 실행한 결과, Gaussian 수는 평균
6,800,491개(표준편차 13,169개, 0.19%)로 dense 기준선 7,682,007개의 0.885배였다. PSNR 은
평균 26.334 dB(표준편차 0.027 dB)로 dense 의 26.300 dB 와 0.034 dB 차이이며, 이는 이
파이프라인의 실행 변동 범위 안이다. 학습 시간은 평균 32.7분으로 dense 의 90.4분보다
2.8배 짧다.

기존 대조군인 block 2 RADC + 다중 view 조건은 Gaussian 이 11,761,154개(dense 의 1.531배),
학습 시간 93.9분이었다. 게이트는 같은 씬에서 Gaussian 수를 42% 줄이고 학습 시간을
2.9배 단축했다.

### 발견 2 — 게이트 없이 ray 를 1/16 로 줄이면 RTX 4090 학습을 완주하지 못한다

같은 조건에서 게이트만 끈 대조 실행은 densification 도중 Gaussian 이 11,894,589개에
이르렀을 때 CUDA out of memory 로 종료됐다. 종료 시점은 densify 사이클 45회, 약
13,700 step 이며 densification 종료 지점인 15,000 step 에 도달하지 못했다.

게이트를 켠 조건의 GPU 메모리 사용량은 `θ = 1.0` 에서 13.2 GB, `θ = 1.5` 에서 8.4 GB였다.
Gaussian 수 통제가 품질 문제 이전에 학습 완주 가능 여부를 정한다. `θ = 1.5` 의 8.4 GB 는
12 GB RTX 4070 SUPER 에서도 학습이 가능한 값이다.

### 발견 3 — 게이트 임계값 `θ` 는 실측된 두 곡선의 교차점으로 계산되며 그 값은 1.95다

게이트 임계값을 임의로 정하지 않고 계산할 수 있다. 되돌려야 할 부풀림 `φ(h)` 와
RADC 축소가 되돌릴 수 있는 최대 배율 `√(1+k(h))` 를 비교하면, `h` 가 작은 구간에서
전자가 후자를 넘는다. 즉 그 구간은 축소를 최대로 적용해도 통계량이 부푼 채로 남는다.

두 곡선 모두 코드에 실측값으로 들어 있다. `_PHI_KNOTS[4]` 와 `_K_OF_H_K` 를 로그-로그
보간해 교차점을 구하면 `h* = 1.953` 이다. `h = 1.5` 에서는 `φ = 2.444`, `√(1+k) = 2.078`
로 보정이 0.366 부족하고, `h = 2.0` 에서는 `φ = 2.044`, `√(1+k) = 2.074` 로 보정이 충분하다.

이번에 시험한 `θ = 1.0` 과 `θ = 1.5` 는 이 계산값보다 낮다. 즉 보정이 부족한 구간을
전부 걷어내지 않은 상태에서도 위 결과가 나왔다.

### 부수 결과 — 게이트를 강하게 걸수록 미교차 Gaussian 이 줄어든다

어느 학습 view 의 ray 도 통과하지 않는 primitive 의 비율을 5개 체크포인트에서 쟀다.
ray 1/16 조건에서 `θ = 1.0` 일 때 26.95~27.25%, `θ = 1.5` 일 때 21.28% 다. 미교차이면서
density 0.005 이상인 개체는 390,872개에서 113,167개로 71% 줄어든다.

게이트는 미교차 개체를 직접 제거하지 않는다. clone 과 split 후보에서 빼는 것뿐이다.
그런데도 미교차 개체가 줄어든 것은, 관측이 부족한 상태에서 만들어진 자식 Gaussian 이
다시 관측되지 않는 위치에 놓이는 경로를 차단한 결과로 해석된다.

## 1. 방법

### 1.1 게이트의 정의

Gaussian `i` 에 대해 densify 주기 동안 다음을 누적한다.

```
h̄_i = (그 주기에 받은 ray 총합) / (그 Gaussian 이 보인 step 수)
```

densify 시점에 `h̄_i ≤ θ` 이면 그 Gaussian 의 `densify_grad_norm_accum` 을 0 으로 만든다.
통계량이 0 이므로 densify 임계값 0.0002 를 넘지 못하고 clone 과 split 후보에서 빠진다.

게이트가 하지 않는 일을 명시한다.

| 항목 | 게이트의 영향 |
|---|---|
| Gaussian 제거 | 없음. pruning 은 density 임계값 0.005 로 판정하는 별도 경로다 |
| 파라미터 학습 | 없음. 위치, 크기, 회전, density, SH 계수가 매 step 갱신된다 |
| 렌더링 | 없음. 화면에 그대로 기여한다 |
| 다음 주기 | 없음. 주기마다 다시 판정하며 누적 버퍼는 전원 초기화된다 |
| clone 과 split | 이번 주기에만 차단된다 |


### 1.2 실행 설정

stump, downsampling 4, 30,000 step, densify 임계값 0.0002 고정. RADC 는
`--hit-shrink --shrink-alpha 1 --online-k`, 다중 view 는 15,000 step 부터 `K = 4`.
RTX 4090 에서 실행했다.

| 조건 | block | step 당 ray | 전체 대비 |
|---|---:|---:|---:|
| dense | — | 1,027,125 | 1 |
| 1/4 | 2 | 257,299 | 1/4 |
| 1/16 | 4 | 64,584 | 1/16 |

다중 view 구간에서는 view 당 block 을 키워 총 ray 예산을 유지한다. block 4 에 `K = 4`
이면 view 당 block 8 로 4개 view 를 쓰며 합계가 64,896개다.

### 2.4a 미교차 Gaussian 비율

학습에 쓴 전체 view 를 dense ray 로 렌더해 `mog_visibility` 로 판정했다. 어느 view 의
ray 도 통과하지 않은 primitive 를 미교차로 센다. alive 기준은 density 0.005 이상이다.

| 조건 | ray | primitive | 기하 미교차 | 비율 | 그중 alive | 그중 dead |
|---|---|---:|---:|---:|---:|---:|
| `θ = 1.0` 1회차 | 1/16 | 6,791,417 | 1,830,094 | 26.95% | 399,973 | 1,430,121 |
| `θ = 1.0` 2회차 | 1/16 | 6,819,478 | 1,858,644 | 27.25% | 394,150 | 1,464,494 |
| `θ = 1.0` 3회차 | 1/16 | 6,790,579 | 1,836,919 | 27.05% | 390,872 | 1,446,047 |
| `θ = 1.5` | 1/16 | 4,318,788 | 918,852 | 21.28% | 113,167 | 805,685 |
| `θ = 1.0` | 1/4 | 6,920,323 | 1,807,633 | 26.12% | 946,218 | 861,415 |

`θ` 를 1.0 에서 1.5 로 올리면 미교차 비율이 27.05% 에서 21.28% 로 내려가고, 미교차이면서
alive 인 개체는 390,872개에서 113,167개로 71% 줄어든다.

ray 예산이 같은 1/16 조건 안에서 `θ` 만 바꾼 비교이므로, 게이트가 미교차 개체의 생성을
억제한다고 볼 수 있다. 미교차 개체는 어느 view 에서도 ray 를 받지 못하므로 gradient 가
0 이고, densification 통계량이 만들어지지 않는다. 게이트가 그런 개체를 직접 제거하지는
않지만, 그런 개체로 자랄 후보를 clone 과 split 단계에서 걸러 낸 결과로 해석된다.

1/4 조건과 1/16 조건을 비교하면 미교차 비율은 26.12% 와 27.05% 로 비슷한데, 그중 alive 인
개체 수가 946,218개와 390,872개로 2.4배 차이가 난다. 1/16 조건에서는 미교차 개체의
대부분(78%)이 density 0.005 미만으로 내려가 있다. 1/4 조건에서는 그 비율이 48% 다.

미교차이면서 alive 인 개체의 opacity 분포를 보면 1/4 조건에서 중앙값 0.01000, 평균
0.06109 이며 946,218개 중 646,865개가 0.01 미만이다. 이들은 alive 판정 기준인 0.005 를
간신히 넘긴 상태다.

## 3. 게이트 임계값의 계산

### 3.1 조건

RADC 축소 인자는 `1/√(1+α·k(h))` 이고 `k(h)` 의 실측 범위가 0.143에서 3.317이므로,
축소 인자는 0.481에서 0.935 사이다. 즉 통계량을 되돌릴 수 있는 최대 배율이 2.08배다.

되돌려야 할 배율은 실측 부풀림 `φ(h)` 다. 두 값을 비교해 다음 조건을 만족하는 구간이
보정 부족 구간이다.

```
φ(h) > √(1 + α·k(h))
```

### 3.2 계산 결과

`_PHI_KNOTS[4]` 와 `_K_OF_H_K` 를 로그-로그 보간했다.

| `h` | 필요한 배율 `φ(h)` | 가능한 배율 `√(1+k(h))` | 차이 | 판정 |
|---:|---:|---:|---:|---|
| 1.0 | 2.568 | 2.078 | +0.490 | 보정 부족 |
| 1.5 | 2.444 | 2.078 | +0.366 | 보정 부족 |
| 1.7 | 2.261 | 2.076 | +0.185 | 보정 부족 |
| 1.953 | 2.075 | 2.074 | 0.000 | 교차점 |
| 2.0 | 2.044 | 2.074 | −0.030 | 보정 충분 |
| 3.0 | 1.704 | 1.996 | −0.292 | 보정 충분 |
| 20.0 | 1.336 | 1.360 | −0.023 | 보정 충분 |

교차점은 `h* = 1.953` 이다.

### 3.3 축소 함수의 형태가 실측 부풀림과 다르다

`φ ≈ √(1+k)` 는 noise 모형에서 유도한 근사다. 실측된 두 곡선을 맞추려면 `α` 가 `h` 마다
달라야 한다.

| `h` | 실측 `φ` | 맞추는 데 필요한 `α` |
|---:|---:|---:|
| 1.5 | 2.444 | 1.50 |
| 3.0 | 1.704 | 0.63 |
| 20.0 | 1.336 | 0.91 |

단일 `α` 로는 두 곡선이 맞지 않는다. 축소 함수 `1/√(1+αk)` 의 형태가 실제 부풀림을
표현하지 못하며 그 차이가 `h` 가 작은 구간에서 가장 크다.

### 3.4 `θ` 를 학습 중에 계산하는 방안

`k(h)` 는 `--online-k` 로 씬마다 다시 측정된다. `φ(h)` 는 `_PHI_KNOTS` 의 정적 표이며
block 4 와 8 만 있다.

`observe()` 에 누적 한 줄을 추가하면 `φ` 도 온라인으로 측정할 수 있다. 현재
`k_sum` 이 `‖μ‖²` 를, `v_sum` 이 `σ²` 를 쌓고 있으므로, `(‖g_A‖ + ‖g_B‖)/2` 를
추가로 쌓으면 `φ̂ = n_sum / √(k_sum)` 이 된다. `k(h)` 와 같은 `h` 구간, 같은 표본에서
나오므로 두 곡선이 정합한다. `refresh()` 에서 교차점을 구하면 `θ` 가 매 주기 갱신된다.

이 경우 손으로 정하는 값이 없어진다.

## 4. `k(h)` 곡선의 선별 편향

곡선은 split-half 관측으로 만든다. 같은 view 에서 독립인 두 표본 A 와 B 를 뽑아,
차 `g_A − g_B` 로 `σ²` 를, 합에서 차 성분을 뺀 값으로 `‖μ‖²` 를 추정한다.

`observe()` 는 두 표본 모두에 맞은 Gaussian 만 사용한다.

```python
both = ((g_a != 0).max(dim=1)[0]) & ((g_b != 0).max(dim=1)[0])
```

한 표본에서 기대 적중 수를 `λ` 라 하면 두 표본 모두에 맞을 확률은 `(1−e^(−λ))²` 다.
`λ = 1` 이면 0.399, `λ = 5` 면 0.987 이다. `h` 가 작은 구간일수록 참여율이 낮고, 참여하는
개체는 그 구간에서 실제 `λ` 가 높은 쪽이다.

따라서 낮은 `h` 구간의 `k` 가 실제보다 작게 측정되고, 축소가 실제로 필요한 양보다
적게 적용된다.

이 편향은 게이트가 배제하는 구간에 있으며, 3.2절의 교차점 계산은 실제로 적용되는
축소량(`k_측정` 기반)을 사용하므로 편향의 영향을 받지 않는다. 다만 편향의 크기를 잰
적이 없다. calibrate 단계만 조밀한 block 으로 실행하면 참여율을 높인 곡선과 비교할 수
있으며, calibrate 가 97 step 마다 한 번 실행되므로 학습 시간 증가는 약 4% 다.
