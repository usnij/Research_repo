# Gaussian cap 산정 규칙과 13씬 고정값

기준일: 2026-11-04. 규칙 이름: `fine_tracks_v1`.
학습 소스 동결 commit: `f472ab69eb6102a0fa7a6a948c4379be335a9c1f`.

## 1. 적용 원칙

학습 전에 **학습 이미지의 미세 대역 비율과 COLMAP의 학습 카메라 관측 관계**로 씬당 하나의 Gaussian cap을 계산한다. 현재 13씬은 16장 표본이 아니라 **전체 학습 이미지**를 사용한다. 입력에 이미지 장수를 직접 곱하는 항은 없다.

산출된 cap은 실행 설정에 저장하여 고정한다. 같은 씬의 `R=1/16`, `R=1/9`, dense MCMC는 같은 cap을 사용한다. E8은 지시된 `cap × 9/16` 축소 조건을 따르고, 원본 ADC 대조군 E3에는 이 cap을 적용하지 않는다. MCMC 성장은 기존 `log_horizon` 일정과 `growth_end=5000`을 그대로 사용하며, 목표 cap에 도달한 뒤 개수를 고정한다. `growth_end`는 0부터 세는 backend step index이므로, 이 일정의 마지막 증가 이벤트는 완료 update 수 기준 5,001번째다. cap 산출과 성장 일정은 별개다.

## 3. 산출식

$$
B=\max(1,\mathrm{round}(\exp(a+b\log F+cU))).
$$

| 계수 | 동결된 값 |
|---|---:|
| a | 15.009178414327616 |
| b | 1.1232071568673763 |
| c | 3.7407898766829666 |

`log`는 자연로그이고 `round`는 Python 내장 반올림을 사용한다. 추가 상한 clipping이나 씬별 분기는 없다. `F ≤ 0`, 유효하지 않은 `U`, 누락된 학습 카메라/track 정보는 오류로 처리한다. 준비 과정에서 cap이 초기 SfM 점 개수보다 작으면 자동 삭제하지 않고 오류로 처리한다.

### 3.1 이미지 특성 F: 미세 대역의 상대 비율

현재 13씬의 불투명 RGB 입력에서는 다음 순서로 계산한다.

1. RGB를 `[0,1]`로 변환한 뒤 `Y = 0.299R + 0.587G + 0.114B`로 밝기를 구한다.
2. 긴 변이 최대 512픽셀이 되도록 비율을 유지해 BOX 방식으로 축소한다. 작은 이미지는 확대하지 않는다.
3. 축소된 밝기 영상에 표준편차 `1, 2, 4, 8`픽셀의 Gaussian 필터를 각각 적용한다. 경계는 `reflect`를 사용한다.
4. 인접한 척도 간 차이의 평균 절댓값을 계산하고, 가장 미세한 차이가 네 대역의 합에서 차지하는 비율을 구한다.
5. 이미지별 비율을 전체 학습 이미지에서 산술평균한다.

$$
L_{v,0}=Y_v,\qquad L_{v,j}=G_{\sigma_j}*Y_v,
\qquad (\sigma_1,\sigma_2,\sigma_3,\sigma_4)=(1,2,4,8).
$$

$$
e_{v,j}=\frac{1}{P_v}\sum_p |L_{v,j-1}(p)-L_{v,j}(p)|,
\qquad
F=\frac{1}{V}\sum_{v=1}^{V}
\frac{e_{v,1}}{\max(\sum_{j=1}^{4}e_{v,j},10^{-8})}.
$$

`V`는 학습 이미지 수, `P_v`는 축소된 이미지의 픽셀 수다. 대역 크기는 **평균 절대 진폭**으로 정의하며 제곱합 에너지가 아니다. 구현은 alpha 입력에도 가중 정규화를 제공하지만, 현재 벤치마크의 준비 단계에서는 RGB 입력만 허용한다.

### 3.2 관측 특성 U: 짧은 SfM track의 비율

기존 COLMAP `images.bin`에서 **학습 카메라에 해당하는 관측만** 선택한다. 유효한 3D point ID를 카메라마다 중복 제거한 뒤, 점 `q`를 관측한 서로 다른 학습 카메라의 수를 `t_q`로 센다.

학습 카메라가 한 번 이상 관측한 점의 집합을 `Q`라고 하면 다음과 같다.

$$
U=\frac{|\{q\in Q:1\le t_q\le 2\}|}{|Q|}.
$$

즉, 학습 카메라 1~2장에만 관측되는 점의 비율이다. 이 값은 학습 카메라 구성과 SfM 결과에 영향을 받는다. 이미지 수의 직접 배수 항이 없다는 사실이 촬영 장수에 대한 불변성을 보장하지는 않는다.

## 4. 계수의 출처

계수는 Counter·Room·Bonsai·Kitchen·Bicycle·Flowers·Garden·Stump·Treehill의 **과거 sparse MCMC 실행 개수 9개**를 이용한 개발 단계의 경험적 보정 결과다. 기준 개수는 2026-09-07 기록의 §4.2에서 추출했고, 2026-10-27 입력 특성 분석에서 다음 절차를 적용했다.

1. 두 입력 특성 `(log F, U)`를 표준화한다.
2. 기준 개수 비율이 `1.1`을 넘는 씬 쌍에 대해, 개수의 대소관계를 비음수 가중치의 logistic ranking으로 적합한다. L2 정규화 계수는 `0.1`이다.
3. 얻은 순위 점수를 기준 개수의 자연로그에 비음수 기울기의 선형식으로 보정한다.
4. 전체 9씬 적합 결과를 위의 `a, b, c` 형태로 환산하고 동결한다.

계수를 적합할 당시 `F`는 학습 이미지 16장의 평균이었다. 이후 `F`를 전체 학습 이미지 평균으로 바꾸었으며, **계수는 다시 적합하지 않았다.** 현재 13씬은 같은 동결 계수를 그대로 적용한 결과다.

따라서 이 규칙은 **과거 개발 씬의 개수 경향을 이용한 입력 기반 cap 규칙**이다. 품질 최적 개수나 품질을 보장하는 최소 개수의 이론적 추정으로 해석하지 않는다. 위 9씬은 계수 개발에 사용되었으므로 독립적인 일반화 검증 집합으로 취급하지 않는다.

## 5. 입력 사용 범위와 재현 근거

- 현재 cap 계산에는 test RGB와 test 품질 지표가 들어가지 않는다. 새로운 씬에서 계수를 적합하거나 test 결과를 보고 cap을 조절하는 단계도 없다.
- `U`는 기존 COLMAP의 관측 관계를 학습 카메라로 제한해 계산한다. **COLMAP 재구성 자체가 test 카메라를 제외하고 수행됐다는 의미는 아니다.**
- 현재 규칙은 Gaussian 다중 척도 차분을 사용하는 `fine_tracks_v1`이다. 예전 Haar 기반 `haar_v1`의 100만/200만/300만 구간식과 구분한다.
- 벤치마크 준비 코드는 `estimate(..., method='fine_tracks_v1', view_limit=None)`로 전체 학습 이미지를 사용하며, 산출값을 실행 설정의 `cap`에 기록한다.
- 11/4 실행은 이미 준비한 정수 cap을 `--budget fixed`로 읽는다. 학습 중 cap을 재추정하거나 보정하지 않는다.
