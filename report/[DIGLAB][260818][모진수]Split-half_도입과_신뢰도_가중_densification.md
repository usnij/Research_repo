# Split-half 도입과 신뢰도 가중 densification (RADC)

작성일 2026-08-18 · 모진수 · 대상 3DGRT, Mip-NeRF 360 실내 3 개 씬 (counter, room, kitchen)

---

## 요약

교수님이 지시하신 split-half 를 densification 통계량에 적용하고, 그 과정에서 통제 알고리즘의 형태를 다시 잡았다. 씬 상수 하나로 임계값을 보정하던 기존 방식 (arm ②) 이 왜 순위를 못 고치는지를 실측으로 확정하고, split-half 를 어디에 놓아야 하는지를 판정했다.

### 발견 1 — split-half 는 편향을 줄이는 대신 분산을 키우는 구조여서, densify 판정에 직접 쓰면 순위를 떨어뜨린다

교차 내적 `g_A · g_B` 는 `‖μ‖²` 의 비편향 추정이다. 그런데 편향을 제거하면 분산이 커진다. 무보정 통계량이 부풀어 있던 양은 편향이면서 동시에 **크고 안정적인 양의 바닥**이었고, 그것을 걷어내면 흔들림은 남은 채 나눌 값만 작아지기 때문이다. counter 1/16 기준으로 상대 표준편차가 1.85 에서 6.93 으로 3.74 배가 되는데, 그중 2.84 배가 편향 제거에서 오고 1.32 배가 Ray 를 반으로 나눈 데서 온다.

순서는 상대적인 흔들림이 정하므로, **정확하지만 불안정한 통계량이 부풀었지만 안정적인 통계량보다 순서를 못 지킨다.** 실제로 편향만 제거한 조건은 상위 1% 중첩이 6 개 조건 중 5 개에서 무보정보다 낮았다 (counter 1/16 에서 34.6% 대 40.0%). counter 에서 학습한 결과도 Gaussian 이 dense 의 130% 로 통제되지 않았고 품질은 개수-품질 교환 곡선 대비 0.162 dB 아래였다.

split-half 가 값을 갖는 자리는 다른 곳이다. **각 Gaussian 을 몇 개의 Ray 가 측정했는지 (h) 와 그때의 noise 대 신호비 k(h) 를 재는 계측기**로 쓰면 그 곡선이 통제 알고리즘의 눈금이 된다.

### 발견 2 — 순위를 회복시키는 것은 편향 제거가 아니라 축소이며, 그 축소는 신뢰도 가중과 같다

축소 (shrinkage) 는 편향 제거와 방향이 반대인 조작이다. 값을 일부러 끌어내려 편향을 넣는 대신 분산을 줄인다. 분산이 이미 지배적인 상황에서 필요한 것이 이쪽이다.

2×2 분해로 편향 제거와 축소를 갈라 측정했다. 축소만 적용하고 편향 제거를 빼면 상위 1% 중첩이 counter 1/16 에서 40.0% 에서 57.9% 로 오르고, 여기에 편향 제거를 더하면 57.0% 로 오히려 내려간다. 6 개 조건 중 4 개에서 축소만이 앞선다. 축소 인자 `1/√(1+k)` 는 고전 검사이론의 신뢰도 `ρ = 1/(1+k)` 의 제곱근과 같은 양이고, split-half 는 그 신뢰도를 추정하는 고전적 방법이다. 도구와 사용처가 원래 짝이다.

### 발견 3 — 신뢰도 가중은 사전 측정 없이 Gaussian 수를 dense 수준으로 통제한다

기존 arm ② 는 씬마다 dense 를 먼저 학습하고 probe 로 배율을 재야 임계값을 정할 수 있었다. 신뢰도 가중은 학습 중 Ray 적중 횟수를 세는 것만으로 작동하며, dense 임계값 0.0002 를 그대로 쓴다. counter 에서 최종 Gaussian 이 dense 의 98%, room 에서 104% 였다. counter 에서 측정한 k(h) 곡선을 room 에 그대로 적용해도 성립했다. 품질은 counter 에서 개수-품질 교환 곡선 대비 +0.020 dB, room 에서 −0.018 dB 로 실행 간 변동 범위 안이며, 판정에는 반복 실행이 필요하다.

## 1. 배경 — 무엇을 고치려는가

### 1.1 sparse Ray 는 gradient 를 편향시키지 않는다

손실이 표집된 픽셀의 평균이므로, 블록 표집으로 얻은 gradient 의 기댓값은 전체 화소로 얻은 값과 같다.

```
g = μ + ε        μ = 전체 화소 기준 gradient,   E[ε] = 0
```

### 1.2 그런데 ADC 는 gradient 가 아니라 그 norm 을 본다

densification 통계량은 step 마다 계산한 norm 을 평균한 것이다 ([gs.py:302](../3dgrut/threedgrut/strategy/gs.py#L302)).

```python
grad_norm = ‖ position.grad × 카메라까지 거리 ‖ / 2
densify_grad_norm = accum / denom
mask = densify_grad_norm >= 0.0002
```

norm 은 볼록함수이므로 `E‖g‖ ≥ ‖E[g]‖ = ‖μ‖` 이고, 등호는 분산이 0 일 때만 성립한다. `ε` 의 평균이 0 이어도 그 길이의 평균은 0 이 아니다.

```
E‖g‖² = ‖μ‖² + E‖ε‖²
```

**방향은 상쇄되지만 크기는 상쇄되지 않는다.**

### 1.3 부풀림의 크기

분산이 Ray 수에 반비례하므로, 표집률 `R` 에서

```
배율 = E‖g_sparse‖ / ‖μ‖ = √(1 + k/R)        k ≡ σ²/‖μ‖²
```

실측으로 확인된 값이다 (260818 중간보고 2.2 절).

| 씬 | 1/16 | 1/36 | 1/64 | k | 예측 오차 |
|---|---:|---:|---:|---:|---|
| room | 1.625 | 2.151 | 2.753 | 0.102 | 0.2~0.5% |
| counter | 1.693 | 2.248 | 2.886 | 0.115 | 0.0~0.7% |
| kitchen | 1.857 | 2.615 | 3.561 | 0.166 | 1.0~4.3% |

통계량이 부풀면 원래 임계값을 못 넘을 Gaussian 이 통과한다. 그 결과 sparse 학습에서 Gaussian 이 dense 의 155~169% 로 늘어난다.

## 2. 명시적 보정 (arm ②) 과 그 한계

### 2.1 방법

배율을 재서 임계값에 곱한다.

```
τ' = 0.0002 × 배율
counter 0.00033865   room 0.00032507   kitchen 0.00037148
```

### 2.2 결과 — 개수는 줄지만 품질은 씬마다 부호가 다르다

실내 3 씬, 1/16 표집, 3 회 반복이다.

| 씬 | arm ① PSNR | arm ② PSNR | 차이 | 표준편차 대비 | arm ① G | arm ② G |
|---|---:|---:|---:|---:|---:|---:|
| counter | 28.466 ± 0.071 | 28.317 ± 0.023 | −0.149 | −2.9σ | 2,126,054 | 992,883 |
| room | 30.161 ± 0.133 | 30.225 ± 0.222 | +0.064 | +0.4σ | 2,359,520 | 1,106,794 |
| kitchen | 29.264 ± 0.144 | 29.680 ± 0.287 | +0.416 | +1.8σ | 2,327,582 | 1,094,437 |

개수는 세 씬 모두 53% 줄고 학습 시간은 34~41% 짧아진다. 품질은 일관되지 않는다.

### 2.3 원인 — 상수배는 순서를 바꿀 수 없다

배율 보정은 모든 Gaussian 의 통계량에 같은 상수를 곱하는 것이므로 **정의상 순서를 바꾸지 못한다.**  clone과 split이 진행되는 상위 1% 집합이 dense 와 얼마나 겹치는지를 측정하면 다음과 같다.

| 씬 | 1/16 | 1/36 | 1/64 |
|---|---:|---:|---:|
| counter | 40.0% | 21.6% | 14.7% |
| room | 35.9% | 21.9% | 15.1% |
| kitchen | 52.8% | 29.7% | 16.5% |

1/64 에서 densification 이 고르는 상위 Gaussian 의 85% 가 dense 와 다르다. **개수를 맞춰도 다른 Gaussian 을 고르고 있다.**

### 2.4 근사가 들어간 지점

`k` 는 원래 Gaussian 마다 다른 양이다.

```
k_i = σ_i² / ‖μ_i‖²
```

arm ② 는 이것을 씬 전체의 중앙값 하나로 대체한다. 그 근사가 순위를 못 고치는 이유이고, 개별 `k_i` 를 알아내는 것이 다음 과제가 된다.

### 2.5 실용적 부담

arm ② 는 배율을 재기 위해 **dense 학습을 먼저 해야 한다.**

```
1. dense 학습              씬당 30~85 분
2. dense 체크포인트로 probe  씬당 10 분 × 표집률
3. 임계값 계산
4. sparse 학습
```

sparse 학습의 목적이 dense 보다 빠르게 학습하는 것인데 dense 를 선행해야 한다. bicycle 처럼 dense 가 메모리에 안 들어가는 씬에서는 배율을 제대로 잴 수 없다.

## 3. split-half 도입

### 3.1 Ray 표본이 두 개 필요한 이유

Ray 표본 하나만 관측하면 미지수가 둘인데 식이 하나다. 여기서 Ray 표본이란 한 step 에서 표집한 Ray 전체를 뜻한다 (1/16 이면 101,400 개).

```
‖g‖² = ‖μ‖² + (ε 크기)
```

관측값이 큰 것이 신호가 커서인지 noise 가 커서인지 구분되지 않는다. arm ② 가 씬 상수로 뭉갤 수밖에 없었던 이유다.

Ray 표본을 두 개 표집하면 식이 하나 늘어난다.

```
g_A = μ + ε_A
g_B = μ + ε_B          ε_A ⟂ ε_B

E[g_A · g_B] = ‖μ‖² + μ·E[ε_B] + E[ε_A]·μ + E[ε_A]·E[ε_B] = ‖μ‖²
```

두 표본의 noise 가 독립이므로 교차항이 기댓값에서 사라진다. **noise가 관측 가능해진다.**

같은 식을 분산 뺄셈 형태로 쓰면 다음과 같고, 두 표기는 항등식이다.

```
‖(g_A + g_B)/2‖² − ‖g_A − g_B‖²/4  ≡  g_A · g_B
```

### 3.2 표집 구조 — Ray 예산을 맞춘다

원래 구현은 두 표본을 각각 목표 표집률로 표집하고 있었다. 그러면 split-half 조건이 무보정 조건의 두 배 Ray 를 쓰게 되어, 순위가 좋아져도 Ray 를 더 썼기 때문이라는 반박을 받는다.

셀을 가로로 두 배 늘려 각 표본의 표집률을 절반으로 낮췄다.

```
목표 1/16 (블록 4)
  무보정      4×4 셀에서 화소 1 개 추출    →  격자 260×390,  101,400 Ray
  split-half  4×8 셀에서 화소 1 개씩 표본 두 개 추출
              →  각 격자 260×195,  50,700 Ray × 2 = 101,400 Ray
```

학습 gradient 도 `(g_A + g_B)/2` 로 합쳐 optimizer 에 넣었다. 한쪽만 쓰면 optimizer 가 절반 Ray 만 보게 되어 densification 과 무관한 이유로 품질이 떨어진다.

### 3.3 집계 — 분모를 세는 기준

한 step 에서 Gaussian 하나는 세 상태 중 하나다.

| 상태 | `squared` 값 |
|---|---|
| 양쪽 다 맞음 | 진짜 추정값 |
| 한쪽만 맞음 | **정확히 0** |
| 둘 다 안 맞음 | 없음 |

한쪽만 맞으면 `g_B = 0` 이므로 `‖g_A/2‖² − ‖g_A‖²/4 = 0` 이다. 이 0 을 평균에 넣느냐에 따라 두 방식으로 구분된다.

```python
hit_a = (g_a != 0).max(dim=1)[0]
hit_b = (g_b != 0).max(dim=1)[0]
touched = hit_a | hit_b      # "하나라도" — 0 이 섞임
both    = hit_a & hit_b      # "양쪽다"  — 0 을 제외
```

counter 1/16 에서 하나라도 맞은 step 중 26.7% 가 한쪽만 맞았다.

### 3.4 순위 회복 결과

학습이 끝난 dense 체크포인트를 고정하고 300 step 누적으로 측정했다. 상위 1% 중첩이다.

| 씬 | 표집률 | 무보정 (= arm ①②) | split-half | 개선 |
|---|---|---:|---:|---:|
| counter | 1/16 | 40.0% | 57.0% | +17.0%p |
| counter | 1/36 | 21.6% | 43.5% | +22.0%p |
| counter | 1/64 | 14.7% | 33.6% | +18.8%p |
| room | 1/16 | 35.9% | 48.5% | +12.6%p |
| room | 1/36 | 21.9% | 35.7% | +13.8%p |
| room | 1/64 | 15.1% | 28.5% | +13.4%p |
| kitchen | 1/16 | 52.8% | 66.6% | +13.8%p |
| kitchen | 1/36 | 29.7% | 55.8% | +26.2%p |
| kitchen | 1/64 | 16.5% | 45.8% | +29.3%p |

**9 개 조건 전부에서 회복한다.** 평균 +18.5%p, 범위 +12.6~+29.3%p 다. 표집이 성길수록 회복 폭이 커진다 (kitchen 1/16 +13.8 → 1/64 +29.3).

무보정 열이 arm ① 과 arm ② 공통값인 이유는 2.3 절에 있다. 상수배는 순서를 바꾸지 않으므로 두 arm 의 순위가 같다.

### 3.5 그런데 크기가 무너진다

여기서 말하는 **통계량의 크기**는 densify 판정에 쓰이는 숫자 자체의 크기다. 같은 모델·같은 view 에 대해 통계량을 두 번 만들어 Gaussian 별로 비를 구하고 중앙값을 취한 값이다.

```
크기 = median_i ( 그 방식의 통계량_i / dense 통계량_i )
```

1.000 이면 dense 와 같은 크기이고, 1 보다 크면 부풀어 있다는 뜻이다. 임계값 0.0002 는 dense 기준으로 정해진 값이므로, 크기가 1 에서 벗어나면 같은 임계값이 dense 와 다른 수의 Gaussian 을 선택한다. 1.692 면 원래 못 넘을 Gaussian 이 대거 통과하고, 0.663 이면 반대로 넘어야 할 것이 막힌다.

**크기는 임계값이 어디를 자르는지를 정하고, 순위는 그 선 위에 누가 있는지를 정한다.** 둘 다 맞아야 dense 와 같은 집합이 선택된다.

| 씬 | 표집률 | 무보정 | split-half |
|---|---|---:|---:|
| counter | 1/16 | 1.692 | 0.663 |
| counter | 1/64 | 2.879 | 0.422 |
| room | 1/64 | 2.740 | 0.330 |
| kitchen | 1/64 | 3.556 | 0.463 |

3.3 절의 0 이 평균을 깎기 때문이다. 분모를 "양쪽 다 맞은 step" 으로 바꾸면 크기가 복원된다 (counter 1/16 에서 0.950, 1/64 에서 1.137). 그런데 그렇게 하면 순위가 무너진다 (34.6%, 11.4% — 무보정보다도 낮다).

**크기와 순위를 동시에 얻지 못한다.** 이 교착이 4 절의 분해로 이어진다.

### 3.6 학습에 적용한 결과 — 개수 통제에 실패한다

3.4 절의 순위 회복이 학습으로 이어지는지 확인하기 위해 counter 에서 30,000 step 을 학습했다 (1/16, 상한 4,000,000, 1 회 실행).

임계값은 arm ② 와 같은 규칙으로 정했다. 자기 통계량의 크기를 재서 임계값에 곱하는 방식이다.

```
arm ②   0.0002 × 1.692 = 0.00033844
arm ③   0.0002 × 0.663 = 0.00013267
```

두 arm 이 같은 방식으로 크기를 맞췄으므로 최종 Gaussian 수가 비슷해야 한다. 결과는 그렇지 않았다.

| | Gaussian | dense 대비 | PSNR |
|---|---:|---:|---:|
| dense | 1,255,427 | 100% | 28.570 |
| arm ② 배율보정 | 992,883 | 79% | 28.317 |
| **arm ③ split-half** | **1,631,010** | **130%** | **28.239** |

**arm ② 의 1.64 배가 나왔다.** 크기를 맞췄는데도 개수가 어긋난다.

성장 궤적을 보면 초반부터 벌어진다.

| step | dense | arm ③ | dense 대비 |
|---|---:|---:|---:|
| 1,000 | 182,681 | 206,619 | 113% |
| 3,000 | 384,509 | 526,829 | 137% |
| 5,000 | 633,682 | 838,555 | 132% |
| 10,000 | 1,036,198 | 1,289,167 | 124% |

원인은 크기를 잰 시점에 있다. 배율 0.663 은 **수렴이 끝난 dense 체크포인트**에서 측정한 값인데, 그 크기를 만드는 것이 3.3 절의 0 희석이고 희석의 세기는 Gaussian 하나를 몇 개의 Ray 가 맞추느냐에 달려 있다. 학습 초반에는 Gaussian 이 155,767 개뿐이라 하나당 Ray 가 많고 양쪽이 다 맞는 일이 잦다. 희석이 약해 통계량이 측정 시점보다 크게 나오고, 0.00013267 이라는 낮은 임계값을 훨씬 많이 통과한다.

**축소 세기가 학습 상태에 따라 변하는데 임계값은 한 시점의 측정으로 고정되어 있다.** 이 어긋남이 5 절에서 축소를 명시적 형태로 바꾸는 이유가 된다. 관측량을 매 step 세면 상태 변화가 자동으로 반영된다.

품질도 개선되지 않았다. arm ① 과 arm ② 를 잇는 개수-품질 교환 곡선에서 1,631,010 개면 28.401 인데 실측이 28.239 로 0.162 dB 아래다 (6.2 절). **probe 에서 얻은 순위 이득이 학습 결과로 이어지지 않았다.**

## 4. 순위 회복의 원인 분해

### 4.1 비편향 추정이 순위를 못 만드는 이유

교차 내적의 분산을 구하면 다음과 같다 (등방 3 차원 기준).

```
g_A · g_B = ‖μ‖² + μ·ε_A + μ·ε_B + ε_A·ε_B
Var       = 2‖μ‖²σ² + 3σ⁴
```

`r ≡ σ²/‖μ‖²` 로 두면 표준편차를 추정 대상으로 나눈 값이 `√(2r + 3r²)` 이다. 우리 조건의 값이다.

| 조건 | 표본 하나의 표집률 | r | 표준편차 / 추정대상 |
|---|---|---:|---:|
| 1/16 예산, 표본 두 개 | 1/32 | 3.68 | **6.9** |
| 1/64 예산, 표본 두 개 | 1/128 | 14.7 | **26.1** |

**한 step 의 추정치는 표준편차가 추정하려는 값의 7~26 배다.** step 별 음수 비율이 22.7~29.2% 로 나오는 것이 이 때문이다.

무보정 통계량과 비교하면 교환 관계가 드러난다 (1/16, r=1.84 기준).

| | 기댓값 | 표준편차 | 표준편차 / 기댓값 |
|---|---:|---:|---:|
| 무보정 `‖g‖²` | 2.84 ‖μ‖² | 5.26 ‖μ‖² | **1.85** |
| 교차 내적 | 1.00 ‖μ‖² | 6.93 ‖μ‖² | **6.93** |

무보정은 2.84 배 부풀어 있지만 자기 크기 대비로는 3.7 배 안정적이다.

편향을 제거했는데 분산이 커지는 것이 언뜻 어긋나 보이지만, 두 통계량을 항으로 갈라 보면 구조가 같다.

```
무보정      ‖g‖²    = ‖μ‖² + 2μ·ε        + ‖ε‖²
교차 내적   g_A·g_B = ‖μ‖² + μ·(ε_A+ε_B) + ε_A·ε_B
```

세 번째 항만 다르다. `‖ε‖²` 는 항상 양수라 기댓값이 0 이 아니고, `ε_A·ε_B` 는 두 noise 가 독립이라 0 이다. **기댓값이 0 이 되었을 뿐 흔들림은 그대로 남는다.** noise 를 제거한 것이 아니라 noise 가 크기에 더하는 몫만 기댓값 수준에서 뺀 것이기 때문이다.

상대 표준편차가 3.74 배가 되는 것을 두 몫으로 나누면 다음과 같다.

```
3.74 배  =  1.32 배 (Ray 를 반으로 나눔)  ×  2.84 배 (편향 제거)
```

Ray 를 반으로 나눈 몫은 표본 하나가 1/32 로 성겨져 분산이 두 배가 되는 데서 온다. **주된 원인은 편향 제거 쪽이다.** 무보정이 부풀어 있던 `‖ε‖²` 는 편향이면서 동시에 크고 안정적인 양의 바닥이었고, 그것을 걷어내면 절대 흔들림은 5.26 에서 6.93 으로 1.32 배 늘었을 뿐인데 나눌 값이 2.84 에서 1.00 으로 줄어 상대적으로는 3.74 배가 된다.

**순서는 상대적인 흔들림이 정한다.** 그래서 일관되게 틀린 값이 들쭉날쭉 맞는 값보다 순서를 더 잘 지킨다.

### 4.2 축소란 무엇인가

여기서 말하는 **축소 (shrinkage)** 는 추정값을 일부러 0 쪽으로 끌어내리는 조작이다. 편향을 넣는 대신 분산을 줄인다. 통계학에서 James-Stein 추정, ridge 회귀, 경험적 베이즈가 같은 계열이다.

편향 제거와는 방향이 반대다.

| | 하는 일 | 편향 | 분산 |
|---|---|---|---|
| 편향 제거 (교차 내적) | noise 를 추정해 뺀다 | 감소 | **증가** |
| 축소 (shrinkage) | 값을 끌어내린다 | **증가** | 감소 |

4.1 절에서 확인한 대로 우리 조건은 분산이 이미 신호의 6.9~26.1 배로 지배적이다. 그런 상황에서 편향을 더 없애는 방향은 손해가 되고, 반대 방향이 필요하다.

**우리 구현에서 축소는 의도해서 넣은 것이 아니라 집계 규칙에서 생겼다.** 3.3 절에서 한쪽 표본만 맞은 step 은 값이 정확히 0 이 되는데, 그 0 을 분모에 세면 평균이 그만큼 내려간다. 두 집계 방식이 곱셈 관계로 이어진다.

```
하나라도 분모 =  양쪽다 분모  ×  ( 양쪽 다 맞은 step 수 / 하나라도 맞은 step 수 )
                 └─── 값 ───┘   └──────── 축소 인자 ────────┘
```

항등식이다. 뒤쪽 인자가 0 과 1 사이의 값이고 **Gaussian 마다 다르다.** counter 1/16 에서 평균 0.733 이었다.

인자의 크기를 정하는 것은 그 Gaussian 을 몇 개의 Ray 가 맞추느냐다. Ray `h` 개를 무작위로 반씩 나눌 때 양쪽에 최소 하나씩 들어갈 확률이 `1 − 2^(1−h)` 이므로, **자주 관측된 Gaussian 은 1 에 가깝고 드물게 스치는 Gaussian 은 0 에 가깝다.**

| h | 축소 인자 |
|---|---:|
| 1 | 0.000 |
| 2 | 0.500 |
| 4 | 0.875 |
| 10 | 0.998 |

즉 이 축소는 **관측이 불안정한 Gaussian 을 선택적으로 눌러 내리는 가중치**로 작동한다. 6.2 절에서 늘어난 Gaussian 의 43.7~54.1% 가 어떤 Ray 와도 교차하지 않는다는 것을 확인했는데, 그 집단이 정확히 이 가중치에 걸린다.

다만 이 형태는 세기를 조절할 수 없고 근거도 집계 규칙에서 나온 것이라, 5 절에서 명시적 형태로 다시 정의한다.

### 4.3 2×2 분해

4.2 절의 항등식을 쓰면 편향 제거와 축소를 갈라서 측정할 수 있다. 축소만 조건은 양쪽 다 맞은 step 에서 교차 내적 대신 **보통의 norm** 을 쌓고, 한쪽만 맞은 step 에는 0 을 쌓되 분모는 하나라도 맞은 step 으로 센다. 축소 인자는 그대로 두고 편향 제거만 뺀 것이다.

네 조건이 이렇게 대응된다.

| 조건 | 편향 제거 | 축소 |
|---|---|---|
| 무보정 | ✗ | ✗ |
| 양쪽다 | ✓ | ✗ |
| 축소만 | ✗ | ✓ |
| split-half (하나라도) | ✓ | ✓ |

상위 1% 중첩이다.

| 씬 | 표집률 | 무보정 | 양쪽다 (편향 제거만) | split-half (둘 다) | **축소만** |
|---|---|---:|---:|---:|---:|
| counter | 1/16 | 40.0% | 34.6% | 57.0% | **57.9%** |
| counter | 1/64 | 14.7% | 11.4% | 33.6% | **39.0%** |
| room | 1/16 | 35.9% | 31.8% | **48.5%** | 47.1% |
| room | 1/64 | 15.1% | 13.5% | 28.5% | **31.4%** |
| kitchen | 1/16 | 52.8% | 53.4% | **66.6%** | 60.4% |
| kitchen | 1/64 | 16.5% | 8.7% | 45.8% | **46.5%** |

읽히는 것이 셋이다.

**편향 제거만 하면 무보정보다 나쁘다.** 6 개 조건 중 5 개에서 그렇다. 4.1 절의 분산 계산과 일치한다.

**축소만 해도 회복한다.** 6 개 조건 전부에서 무보정을 크게 넘는다.

**축소에 편향 제거를 더하면 4/6 에서 오히려 낮아진다.** 1/64 세 조건은 전부 축소만이 이긴다 (+5.4, +2.9, +0.7%p). 표집이 성길수록 교차 내적의 흔들림이 커지므로 방향이 일치한다.

### 4.4 축소는 크기도 고친다

| 씬 | 표집률 | 무보정 | 축소만 |
|---|---|---:|---:|
| counter | 1/16 | 1.692 | 1.237 |
| counter | 1/64 | 2.879 | 1.137 |
| kitchen | 1/64 | 3.556 | 1.215 |
| room | 1/64 | 2.740 | 0.947 |

축소 인자가 부풀림과 같은 변수에 연동되기 때문이다. 적게 관측된 Gaussian 이 가장 심하게 부풀고 동시에 가장 많이 깎이므로 두 효과가 상쇄된다.

**축소만이 크기와 순위를 동시에 개선하는 유일한 조건이다.**

## 5. 신뢰도 가중 densification (RADC)

### 5.1 축소 인자의 정체

4.2 절의 축소 인자는 집계 규칙의 부산물이라 세기를 조절할 수 없고 근거도 없다. 명시적 형태로 바꾸면 다음과 같다.

부풀림이 `√(1 + k_i)` 이므로 (표집률에서 잰 `k_i` 기준), 되돌리는 인자는 그 역수다.

```
통계량_i = ‖g_i‖ / √(1 + k_i)
```

고전 검사이론의 **신뢰도** 가 이렇게 정의된다.

```
ρ = 참값 분산 / 관측 분산 = ‖μ‖² / (‖μ‖² + σ²) = 1 / (1 + k)
```

**축소 인자가 `√ρ` 와 같은 양이다.** 통계량에 신뢰도의 제곱근을 곱하는 것이고, split-half 는 그 신뢰도를 추정하는 고전적 방법이다 (split-half reliability). 도구와 사용처가 원래 짝이며, 3 절에서 split-half 를 판정에 직접 쓰면 안 되고 계측에 써야 한다는 결론이 이 이론에서는 자연스러운 배치다.

이 방법을 **RADC (Reliability-Aware Density Control)** 로 부른다. 기존 ADC 의 확장이다.

### 5.2 `k_i` 의 추정 대상

Gaussian 마다 직접 추정하면 4.1 절의 흔들림을 그대로 받는다. 대신 **관측 가능한 양의 함수로 둔다.**

그 Gaussian 을 몇 개의 Ray 가 맞췄는지를 `h_i` 라 하면, 검사이론의 문항 수에 해당한다. 문항이 많을수록 신뢰도가 오른다 (Spearman-Brown).

```
통계량_i = ‖g_i‖ / √(1 + k(h_i))
```

세 층위로 정리하면 위치가 분명해진다.

| | 방식 | 보정 인자 |
|---|---|---|
| 0 차 (arm ②) | 씬 전체를 중앙값 하나로 | 모두 같은 수 |
| **1 차 (RADC)** | **관측량 `h_i` 의 함수로** | **`h` 가 같으면 같은 수** |
| 완전 (split-half) | 각 Gaussian 이 자기 자료로 | Gaussian 마다 다른 수 |

RADC 는 중간이다. 개별성은 `h_i` 로 들어오고 추정의 안정성은 묶음에서 온다. 경험적 베이즈의 구조와 같다.

### 5.3 `h_i` 측정

3DGRT 의 forward 커널이 Gaussian 별 가시성을 0/1 깃발로 기록하고 있었다. 이를 누적으로 바꿨다 ([referenceOptix.cu:161](../3dgrut/threedgrt_tracer/src/kernels/cuda/referenceOptix.cu#L161)).

```cuda
// 기존
params.particleVisibility[rayHit.particleId] = 1;
// 변경
atomicAdd(&params.particleVisibility[rayHit.particleId], 1);
```

한 줄이고, 기존 소비처는 전부 `> 0` 또는 `.bool()` 로 읽으므로 동작이 바뀌지 않는다. 버퍼가 float32 로 할당되는데 커널이 int32 포인터로 쓰는 불일치가 원래부터 있어, Python 에서 개수로 읽으려면 `.view(torch.int32)` 로 재해석해야 한다.

counter dense, full Ray 한 view 에서 측정한 `h` 분포다.

```
0 이 아닌 Gaussian  231,281 / 1,255,427
h  중앙값 63   평균 254.5   최대 54,145
   q25 20   q75 195   q90 563   q99 3,116
```

**25 배 이상 퍼져 있다.** 표집률 1/16 에서는 이 값이 16 분의 1 로 감소해 중앙값 4.58, q25 2.28, q90 23.1 이다.

### 5.4 `k(h)` 곡선 측정

split-half 로 Gaussian 별 `‖μ̂_i‖²` 과 `σ̂_i²` 을 얻고, `h` 구간별로 묶어 중앙값을 낸다. 묶음마다 1~18 만 개를 평균하므로 개별 추정의 흔들림이 사라진다.

| 11 | 2.318 | 1.237 | 1.87 |
| 28 | 1.268 | 0.667 | 1.90 |
| 80 | 0.604 | 0.311 | 1.94 |
| 150 | 0.286 | 0.143 | **2.00** |

`h` 가 클수록 2.00 에 수렴한다. 작은 `h` 에서 벗어나는 것은 반쪽으로 나눌 때 한쪽이 비는 일이 잦아 추정이 무너지기 때문이다.

**씬 배율과의 대조.** counter 1/16 의 씬 배율 1.692 에서 역산하면 `k = 1.692² − 1 = 1.863` 이다. 전율 쌍으로 측정한 `k_i` 중앙값이 1.91 로 1.5% 이내에서 일치한다. 절반 표집률 측정값 2.81 은 크게 어긋났다.

### 5.6 `k_i` 가 상수가 아니라는 직접 증거

전율 쌍 측정에서 얻은 `k_i` 분포다 (counter 1/16, 추정 가능 918,771 개).

```
q10 = 0.342   q25 = 0.821   q50 = 1.91   q75 = 4.53   q90 = 11.5
사분위폭 / 중앙값 = 1.94
```

**10 분위와 90 분위가 34 배 차이 나고 사분위폭이 중앙값의 1.94 배다.** arm ② 가 상수 하나로 대체할 수 있으려면 이 값이 0 에 가까워야 한다. 2.4 절의 근사가 왜 순위를 못 고치는지에 대한 직접 측정값이다.

### 5.7 알고리즘 정의

```
[오프라인 1 회]
  dense 또는 임의의 체크포인트에서
    Ray 표본 두 개를 각각 목표 표집률로 표집해 g_A, g_B 를 얻고
    ‖μ̂_i‖² = mean_step( g_A · g_B )
    σ̂_i²   = mean_step( ‖g_A − g_B‖² / 2 )
    k̂_i    = σ̂_i² / ‖μ̂_i‖²
  h 구간별로 묶어 k(h) 곡선을 만든다

[학습 중, 매 step]
  forward 커널이 Gaussian 별 Ray 적중 횟수 h_i 를 센다
  통계량_i += ‖ g_i × 거리 ‖ / 2  ×  1/√(1 + α·k(h_i))
  분모_i   += 1

[densify 시점]
  mask = 통계량 >= 0.0002        ← dense 기준 임계값 그대로
```

`α` 는 축소 세기다. 크기를 참값으로 되돌리는 값이 `α=1` 이고, 5.4 절의 곡선이 그 눈금이다. 6.4 절에서 판정 중이다.

### 6.3 읽히는 것

**개수 통제는 성공했다.** RADC 는 dense 임계값 0.0002 를 그대로 쓰면서 counter 98%, room 104% 에 착지했다. arm ② 는 같은 임계값을 쓰면 arm ① 이 되어 169% 로 간다. **사전 배율 측정도, dense 학습도 없다.** counter 에서 측정한 곡선이 room 에서 그대로 작동한 것도 확인됐다.

**arm ③④ 의 미달은 표집 탓으로 보인다.** 통계량이 전혀 다른 두 arm 이 −0.162 와 −0.131 로 비슷하게 미달했고, 표집을 arm ① 과 같게 되돌린 arm ⑤ 에서 곡선 위로 올라갔다.

**품질 이득은 아직 확정할 수 없다.** counter +0.020, room −0.018 은 실행 간 표준편차 (0.023~0.071 dB) 안이다. 각 1 회 실행이다.
