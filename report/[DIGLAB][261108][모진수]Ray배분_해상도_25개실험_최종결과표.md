# Ray 배분·해상도 실험 최종 결과표

작성일: 2026-11-08. 교수님 지시의 **실험 1(12개) + 실험 2(13개), 총 25개**에 대한 최종 결과입니다. 이전 지시의 E1/E2와 구분하여, 아래 E1/E2는 `ray_allocation_resolution_261108` 캠페인 안의 실험 번호를 뜻합니다.

학습·평가 25/25 완료. 실행당 7개 시점, 총 175개 체크포인트 평가 및 30k test view 723개 기록을 확보했습니다. 최종 30k 모델·optimizer·설정·로그·평가 증거를 로컬 백업했고, 파기 전 백업 1,740개 파일의 SHA256을 재검증했습니다. 1–4번 인스턴스는 백업 확인 후 사용자 승인으로 파기했습니다.

## 1. 공통 조건과 읽는 방법

- 고정 학습 코드 commit: `dec85dfec2a5a66e08b3633e3f14fc1cc597f49c`. 결과 CSV 게시 commit: `2fc86de`.
- RTX 4090, seed 777, 30,000 step. 동일 씬은 같은 인스턴스에서 순차 실행했습니다.
- MCMC: 100 step마다 5% 성장, 씬별 cap 유지. 기록된 적용 구간은 `500 < index < 25000`이며 cap 도달 step을 강제하지 않았습니다.
- 손실: 0.8 L1 + 0.2 SSIM, opacity·scale 정규화 각각 0.01, `observed_only=false`.
- Dense 학습 SSIM: 학습 이미지 기준 window 11, σ1.5. Sparse는 아래에 명시한 좌표 SSIM을 사용했습니다.
- 평가: 2k·5k·7k·10k·15k·20k·30k, test view 전체·전체 ray. 모든 실행의 평가 SSIM은 `eval_full.py`의 torchmetrics 표준 SSIM입니다. 저해상도 dense도 목표 해상도로 렌더해 평가했습니다.
- 학습시간은 CUDA 동기화를 포함한 학습 반복 누적 시간이며 저장·평가 시간은 제외합니다. 평균 step 시간은 **총 학습시간 / 30,000**입니다. cap 도달 후 중앙값과는 다른 값입니다.
- VRAM은 로그에 기록된 GPU 전체 사용량 최대치이며, 표는 **학습 / 평가 MiB** 순서입니다. torch allocator 최대치와 구분합니다.

## 4. 구현상 조정과 해석 제한

1. **시간 스케줄의 정확한 ray 예산:** 단순히 block 8/5를 절반씩 사용하면 block 6과 정확히 같은 총량이 되지 않습니다. 실제 실행은 뒤쪽 예산을 `2 × N6 − N8`로 맞추고 block 5 후보를 균등하게 줄였습니다. Arm 2·4의 `settings_changes`에 기록돼 있습니다.
2. **고해상도 sparse와 저해상도 dense의 ray 수:** Bonsai는 두 비교 모두 정확히 일치합니다. Counter와 Garden은 이미지 크기·블록 경계 반올림 때문에 위 표의 0.257~0.786% 차이가 있습니다. 명목 표집률과 실제 R을 구분해야 합니다.
3. **같은 ray 수 ≠ 같은 계산시간:** E1은 누적 ray가 같아도 시간이 달랐습니다. 이 표만으로 원인을 확정할 수 없습니다. Gaussian 성장 단계별 ray 배분, hit/ray, 표집·점수 갱신·SSIM 비용을 분해해야 원인을 구분할 수 있습니다.
4. **해상도 간 비교:** Counter E1은 DS2, E2는 DS1 평가입니다. Garden E1은 DS4, E2는 DS2 평가입니다. 두 실험의 PSNR·SSIM·LPIPS를 같은 조건처럼 직접 비교하지 않습니다.
5. **해상도가 높을수록 이득이 커지는가:** 고해상도에서의 속도비와 저해상도 dense 대비 품질 이점은 위 표로 확인할 수 있습니다. 해상도만 바꿨을 때 속도 이득이 단조 증가한다는 주장은, 나머지 조건·표집률까지 맞춘 별도 비교 없이 확정하지 않습니다.
6. **실행 중 설정 변경:** 원본 `settings_changes`에는 Arm 2·4의 예산 보정 외에는 `NA`입니다. 모든 실행은 동일 commit입니다. 실패/OOM으로 기록된 실행은 없습니다. 단일 seed 결과이며 통계적 유의성을 주장하지 않습니다.
7. **별도 분석:** 잔차 상위 20% block의 오차 집중도와 상세 시간 원인 분석은 이 30k 결과표의 수치에 포함하지 않았습니다. 결과가 있는 것처럼 추정치를 넣지 않았습니다.
